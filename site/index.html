Case study · November 2026

Study guides that are not allowed to make things up.

Naman Singh · an unofficial student project

Abstract. A pipeline of language-model agents, Python tools and one LaTeX style turns a course's lecture notes and past exam papers into a print-ready study guide. The model is treated as untrusted: every stage has to pass a check that the writer cannot influence before the next one runs. It has produced guides for 12 courses.

1Version 1 wrote a convincing 2024 paper. None of it was real.

0/13questions in the first version's “2024 past paper” that appear in the real exam.

The first version was one long prompt. Its guides looked finished, and that chapter read like the real thing until it was checked against the scanned paper.

A student who trusts an invented paper studies the wrong things. So the second version was rebuilt around one rule: a stage counts as done only when a check that the writer cannot influence says so.

  1. Past-paper questions come only from a bank transcribed from page images.
  2. Each printed question carries a cropped image of the original, its receipt.
  3. Every numerical answer has a Python check that runs on each build.

2Nine stages, and a gate between them.

Select a stage. Those marked gate stop the run on failure, and nothing downstream is written.

3The verbatim gate, running in your browser.

On the left, what the scanned paper says. On the right, what an agent transcribed. Edit the transcription, or tamper with it, and see whether it would be allowed into a guide.

4What to study when only a few hours are left.

The planner turns the verified bank into a marks model per topic, simulates papers under the exam's choice rules, and picks the question ideas that cover the most expected marks for a 3, 6 or 12-hour budget. Those plans set the study order of the whole guide.

The plans are nested: a longer plan only adds to a shorter one, so the guide can print one list with cut-off lines. Move the line.

5Inside a guide.

Pages from the Computer Networks guide, 281 pages. Select one to read it. These are notes and planner pages; no exam paper is reproduced here, though Plate 6 works an example on a past question's numbers.

Every guide holds unit notes with step-by-step storyboards; every past paper in the window, solved, with each idea solved once and cross-linked; important questions in study order; a short-answer drill and a mock paper; a cheatsheet and a night-before sheet; Anki flashcards and a static web edition with a self-test mode.

Remark (what the numbers do not show yet). The planner's 6-hour plan covered 0.41 of the marks on held-out papers, against 0.36 for picking ideas at random. With four folds that gap is not conclusive, and per-idea probabilities are no better than a flat base rate. So the study plans rank ideas by the marks they cover, the guides show likelihood only as a band when a course has fewer than four papers, and the percentages they print otherwise should be read as rough. One course had no past papers at all; the pipeline runs it in a labelled weak-input mode instead of pretending.

7Built like software, not like a prompt.

Test first, journaled.
Each of the 34 changes started from a failing test or check and is recorded with its scores in an append-only journal; a revert would be recorded the same way, and none has been needed yet.
A regression suite on synthetic fixtures.
28 test files, about 5,700 lines, alongside 11,600 lines of tools. Every bug found on real material became a test.
Resumable by design.
A ledger records each finished step, so a run that stops at a usage limit continues where it left off.
Parallel agents that cannot collide.
Writers own named files and compile only their own pieces against one shared LaTeX style.
Model tiers chosen by evidence.
Cheap models run checks, mid-tier models write under gates, and the top model keeps the judgment calls.
Local CI.
The whole gate runs on a laptop with one command. Hosted CI is manual and only smoke-tests a fresh clone.

Built with Claude Code agents, Python 3.12, LaTeX and TikZ, PyMuPDF, Tesseract OCR, a Monte-Carlo coverage planner and a static web export.

8Future work.

  1. Score the planner after each real exam. Bank the new paper, run the post-exam scorer, and publish predicted against actual coverage per course. This is the data the planner needs to be calibrated.
  2. A convention-consistency checker. Most real review findings were one fact stated two ways. Decide conventions before writing and check every boxed answer against them.
  3. A fully public sample guide. Run the pipeline on openly licensed course material, so a complete guide and its web edition can be published without anyone's exam papers.
  4. A planner that beats the base rate. Pool evidence across courses with a hierarchical model, and report calibration as well as coverage.
  5. Cheaper orchestration. The orchestrating session is now the largest cost line. Batch its turns and move whole phases into single commands.
  6. Other universities, other agent runners. The pipeline is plain files. Package the subject template and run it under a second coding agent.
  7. Close the loop with readers. An error-report form whose confirmed reports become regression tests, and spaced repetition in the web edition.
